C07. Compresión de datos

Este capítulo arranca en la teoría de la información: cuántos bits cuesta comunicar un evento, la entropía de Shannon como promedio de esos bits y la entropía cruzada con su castigo, la divergencia de Kullback-Leibler. Con ese piso teórico recorre los cuatro métodos de compresión sin pérdida, de la reducción naive a la compresión aritmética. Cierra en el plano más abstracto: la complejidad de Kolmogorov (incomputable, pero aproximable con un compresor real vía NCD) y la inducción de Solomonoff, que junta a Epicuro, la navaja de Ockam y Bayes en una sola fórmula.

Teoría de la información

Se introduce el concepto de bits de información para entender cuánta información se comunica en un mensaje, más allá de la longitud del mismo. Los bits de información que se necesitan para comunicar un evento i se calculan como:

bitsP(i) = −log2(P(i))

siendo P(i) la probabilidad de que suceda el hecho i. Con ajuste de Laplace:

P(i) = (i + 1) / (tot + 2)
A mayor probabilidad de que pase algo, se «transmite menos» avisando el hecho, por lo que necesita menos bits. Lo improbable es lo informativo.

Entropía de Shannon

Entropía de Shannon. Cantidad promedio de bits que se gastarán por cada mensaje transmitido.
H = Σi=1..n ( bitsP(i) × P(i) )

Entropía cruzada

Se calcula la cantidad promedio de bits por cada mensaje, pero con un sistema de probabilidades (Q) distinto al calculado con los bits de información.

H(P,Q) = Σi=1..n ( bitsP(i) × Q(i) ) = HP + DKL(P ‖ Q)

siendo DKL(P‖Q) la divergencia de Kullback-Leibler. Mide qué tan distintas son las predicciones de las probabilidades reales.

Lectura de la fórmula: la entropía cruzada es siempre la entropía real más un castigo. Ese castigo es la divergencia KL, y vale 0 solo si Q = P. Por eso se usa como función de pérdida en clasificación: minimizar la entropía cruzada es minimizar cuánto se aparta el modelo de la distribución real.

Compresión sin pérdida. Reducir el tamaño de un archivo sin perder información, permitiendo reconstruir el original idénticamente.

Complejidad de Kolmogorov

Complejidad de Kolmogorov. Sea x un string, se define K(x) como la cantidad mínima de bits que debe tener un programa que genere x.

Propiedades

  • Cotas: 0 ≤ K(x) ≤ len(x)
  • Es incomputable
Que sea incomputable es el punto que hace falta para entender el resto: como K(x) no se puede calcular, todo lo que se construye encima (la distancia de Kolmogorov, la inducción de Solomonoff) es teórico y en la práctica se aproxima con un compresor real.

Distancia de Kolmogorov

Calcula qué tan distinto es el programa que genera x en comparación con el que genera y.

KD(x,y) = K(xy) − min { K(x), K(y) }

Su distancia normalizada divide por el máximo de las distancias:

NKD(x,y) = KD(x,y) / max { K(x), K(y) }

Se aproxima con un compresor real, usando las longitudes de las cadenas comprimidas para estimar la distancia:

NCD(x,y) = ( C(xy) − min { C(x), C(y) } ) / max { C(x), C(y) }

Inducción de Solomonoff

PrincipioQué dice
Principio de Epicuro«Si más de una teoría es consistente con los datos observados, no descartar ninguna»
Navaja de Ockam«Quedarse con la teoría más simple consistente con las observaciones»

Procedimiento

  1. Recolectar evidencia en formato entrada → salida
  2. Iterar todos los programas posibles que predigan lo que estamos buscando. Si terminan, miramos su salida dada la entrada que buscábamos según el dato actual
  3. Actualizamos la probabilidad de que cada programa sea el que explique el fenómeno
  4. Repetir con datos nuevos
P(Hi | E) = P(E | Hi) × P(Hi) / P(E)
TérminoQué significa
P(Hi | E)Probabilidad de que el programa Hi explique la evidencia E
P(E | Hi)Probabilidad de E dado el programa Hi. Si lo explicó (o sea, el programa es válido), vale 1
P(Hi)Probabilidad de que el programa Hi sea cierto = 2−K(Hi)
P(E)Probabilidad de la evidencia E: suma de todos los Hi que explican E
Dónde se juntan las dos ideas: P(Hi) = 2−K(Hi) es la navaja de Ockam escrita en fórmula: cuanto más corto (menos complejo) el programa, más probable a priori. Y como no se descarta ningún programa consistente, sino que se les reparte probabilidad, eso es el principio de Epicuro.
